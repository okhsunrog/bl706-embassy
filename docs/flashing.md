# Pinecil V2 flash and RTT workflow

The default `heartbeat` example replaces the active IronOS boot image with this
project's firmware. Keep a verified full original flash backup before first use.
This is a bring-up program: GPIO21 is held low and there is no heater controller.

## Host setup

Use the patched `okhsunrog/probe-rs` branch `fix/jtagprobe-bl706` (flash support
requires `4884829b503b29a3519c1e424402a6c4ec437d95` or later). A stock release does not
include these target/reset/flash changes. The globally installed CLI on the test
host is built from that checkout. Python runs through uv without extra packages.

The standalone Pico runs Grapple Probe Pico, wired as documented in
`tools/pinecil-v2.cfg`. Only JTAG and GND are needed for flashing and RTT; no UART
or target reset wire is required. Select the probe with `PROBE_RS_PROBE` if more
than one CMSIS-DAP is connected.

From this workspace root:

```sh
cargo run -r
# Stop the RTT terminal with Ctrl+C, then run the same command again.
```

The Cargo target is RV32IMC and the default binary is `heartbeat`. The runner
prepares `target/riscv32imc-unknown-none-elf/release/heartbeat.flash.elf`, then runs
`probe-rs run --chip BL706 --protocol jtag --speed 1000 --verify`. Flash verification
is enabled on every invocation. Further Cargo arguments after `--` go to probe-rs.
To prepare an ELF for inspection without connecting or flashing:

```sh
cargo build -r
uv run --no-project tools/flash_image.py target/riscv32imc-unknown-none-elf/release/heartbeat
```

## Boot layout

- Physical flash offset `0`: 176-byte BL702 boot header with the Pinecil V2
  Macronix `C2 20 14` configuration, RC32M, and nominal 8 MHz SPI.
- Physical offset `0x1000`: XIP bootstrap, followed by initialized RAM sections.
  ROM maps this offset at XIP address `0x23000000`.
- The bootstrap copies startup/vectors to `0x22014000` and code/constants/data to
  `0x22020000`. The program then initializes SP/GP, clears BSS, and starts Embassy.
- The first 16 KiB ILM window is excluded from this flash bootstrap's copies.
  On this BL706 after ROM flash startup, CPU stores to `0x22010000` and its
  `0x42010000` alias were ignored; stores at `0x22014000` and OCRAM succeeded.
  This matches the RAM layout reserved by the current BL702 SDK flash linker.
- Upper OCRAM remains reserved as in the RAM-only configuration. No boot2,
  partition manager, or second IronOS application is used.

The linker emits physical flash load addresses while retaining execution/debug
symbols in RAM. Header configuration/data CRC32, full header CRC32 and image
SHA256 are generated by `tools/flash_image.py`; ROM CRC/hash checks stay enabled.
Padding is erased `0xff`. The runner checks architecture, bounds, overlap and
ELF truncation before touching the target. ELF audits check that the linear copies
reproduce every initialized RAM section.

This is a RAM-executed application stored in flash. Moving the main application
to XIP is a separate follow-up; it does not change the intended Cargo/RTT workflow.

## Hardware validation, 2026-11-04

Pinecil V2 BL706, standalone Grapple Probe Pico, 1 MHz JTAG, no UART or reset wire:
10 consecutive `cargo run -r` cycles erased/programmed/verified flash and produced
fresh RTT `tick=0` and `tick=1`, without button presses or USB reconnections.
Time to these logs was about 6.9 seconds per cycle. The initial firmware image
payload was 14,944 bytes, with all 20 KiB covering the used sectors read back and
its payload SHA256 checked against the generated header during development.

An ordinary software system reset also booted the flash bootstrap and ran the
RAM heartbeat. A `cargo run -r` after deliberately parking the CPU in an infinite
RAM loop also recovered and produced fresh startup/timer logs. GPIO21 was an
enabled output with its latch/pad low, and the fatal-trap record was all zero.
These checks do not by themselves prove a physical power-cycle
or validate the other peripheral examples.
